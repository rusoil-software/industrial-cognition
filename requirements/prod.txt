# This file is installed in BOTH production images:
#
#   src/api/Dockerfile           -> api, camera, robot   (FastAPI service)
#   src/vision/Dockerfile.worker -> vision               (Celery worker)
#
# It is therefore the union of the runtime dependency sets, and deliberately
# EXCLUDES anything that only exists to build, test or debug:
#
#   * dev.txt / pytest / ruff            - test and lint tooling
#   * export.txt / torch / transformers  - the one-off OWLv2 -> ONNX export
#     (scripts/export_model.py), which runs on a workstation or in CI and never
#     in a serving container
#   * k8s.txt                            - manifest validation tooling
#
# The two serving images still differ, because their inference providers
# genuinely conflict and cannot be resolved together:
#
#   * `api`    installs opencv + `onnxruntime`     (CPU inference; the documented
#     fallback in doc/k8s.md §8)
#   * `vision` installs opencv + `onnxruntime-gpu` (the GPU path)
#
# `onnxruntime==1.24.4` and `onnxruntime-gpu==1.24.4` ship the same
# `onnxruntime` import package and are mutually exclusive in one environment.
# That is why the provider line at the bottom is a choice, and why
# `src/vision/Dockerfile.worker` installs `requirements/vision.txt` followed by
# `requirements/api.txt` rather than one merged list. See doc/k8s.md §2.
#
# Everything here is pinned to versions already present in requirements/api.txt,
# requirements/base.txt or requirements/vision.txt.
